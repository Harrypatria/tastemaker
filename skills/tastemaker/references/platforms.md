# Platform Adapters

Detect the platform from the tools you have and the files you can see, then follow its row. Ready-to-paste prompts for each platform live in `dist/` (generated by `scripts/build-adapters.mjs`).

| Platform | How Tastemaker loads | Delivery behaviour | Constraints to respect |
|---|---|---|---|
| **Claude Code** | Plugin (`/plugin install`), skills auto-trigger; `/tastemaker`, `/taste-audit`, `/tastemaker-scan` commands; PostToolUse hook scans every edited UI file | Write real files (`src/components/{ui,molecules,organisms}`). Run typecheck, lint, build, `tastemaker scan`; fix up to 3 cycles | Hook feedback arrives as tool errors: fix them, do not argue with them |
| **Claude.ai** (chat, Projects, Artifacts) | Upload skill zip, or paste `dist/system-prompt.md` into Project instructions | One self-contained artifact per deliverable (React + Tailwind or single HTML). Banners and decks as single HTML | No local build: do a static trace and say "not executed" |
| **Google AI Studio** | Paste `dist/system-prompt.md` into System instructions (chat) or the app prompt (Build mode) | Code blocks plus a one-line manifest. In Build mode keep the generated React + TypeScript layout; put model calls in `services/` | Output caps: split by organism and state what comes next. No secrets in client code |
| **Lovable** | `dist/lovable-knowledge.md` into Project Knowledge | Lovable runs React, Vite, TypeScript, Tailwind and shadcn/ui: use its `src/components/ui` primitives and `index.css` variables | Preview must render on first run; mocks behind `src/services/`; Supabase only when the user asks for a backend |
| **Replit Agent** | `dist/replit.md` at repo root | Full-stack-ready files; one `run` command; seed data so the first preview is populated | No missing env vars at boot; bind the server to `0.0.0.0` |
| **Bolt / StackBlitz** | `dist/system-prompt.md` into project prompt | Vite + React default; keep dependency list short (WebContainer installs) | No native modules |
| **v0** | `dist/system-prompt.md` into project instructions | Next.js App Router + shadcn/ui; Server Components by default | `'use client'` only on interactive leaves |
| **Cursor** | `dist/cursor/tastemaker.mdc` into `.cursor/rules/` | Edits in place; run scan via terminal | Rule type "Agent Requested" keeps tokens low |
| **Windsurf** | `dist/windsurf/tastemaker.md` into `.windsurf/rules/` | Same as Cursor | |
| **Codex, Jules, Aider, other AGENTS.md readers** | `dist/AGENTS.md` at repo root | Same as Claude Code without the hook: run `npx tastemaker scan` manually | |
| **Gemini CLI** | `dist/GEMINI.md` at repo root | Same as Claude Code without the hook | |
| **GitHub Copilot** | `dist/copilot-instructions.md` into `.github/` | Suggestions follow the contract; CI runs `tastemaker scan` | |

## Vibe-coding guardrails (all chat builders)

- First message of a new app: state the 8-line Design Decision from taste-direction before code, so the user can redirect early and cheaply.
- Each follow-up prompt edits the smallest surface. Never regenerate a working page to change one component.
- When the platform regenerates whole files, restate the token block at the top of the response so the theme survives.
- Prefer the platform's own primitives (Lovable/v0 shadcn, AI Studio's generated structure) over adding a second kit.
